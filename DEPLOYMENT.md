# PositionedUp — Deployment Guide

> Deploy the full stack: Web App (Vercel) + API (Vercel) + Agent Squad (VPS + Docker)

---

## Prerequisites

| Requirement | Purpose |
|-------------|---------|
| **Vercel account** | Hosts Next.js frontend + FastAPI backend |
| **Supabase project** | Database, Auth, pgvector |
| **VPS** (2GB+ RAM, Ubuntu 22.04) | Runs OpenClaw agent squad 24/7 |
| **OpenAI API key** | LLM for agents (GPT-4o, GPT-4o-mini) |
| **Anthropic API key** | Copywriter agent (Claude Sonnet) |
| **Domain** (optional) | Custom domain for the web app |

Recommended VPS providers: DigitalOcean ($12/mo), Hetzner ($5/mo), Hostinger ($10/mo).

## Part 1: Deploy Web App + API to Vercel

### 1.1 Push Code to GitHub

```bash
git add -A
git commit -m "deploy: production-ready"
git push origin main
```

### 1.2 Import to Vercel

1. Go to [vercel.com/new](https://vercel.com/new)
2. Import your GitHub repository
3. Configure two projects:

**Project A — Frontend (Next.js)**
- Root Directory: `apps/web`
- Framework: Next.js
- Build Command: `pnpm build` (auto-detected)
- Output Directory: `.next`

**Project B — Backend (FastAPI)**
- Root Directory: `apps/api`
- Framework: Other
- Build Command: `pip install -r requirements.txt`
- Output Directory: (leave empty)

### 1.3 Set Environment Variables (Vercel Dashboard)

**Frontend (`apps/web`):**

| Variable | Value |
|----------|-------|
| `NEXT_PUBLIC_API_URL` | `https://your-api-project.vercel.app` |
| `NEXT_PUBLIC_SUPABASE_URL` | Your Supabase URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Your Supabase anon key |

**Backend (`apps/api`):**

| Variable | Value |
|----------|-------|
| `SUPABASE_URL` | Your Supabase URL |
| `SUPABASE_SERVICE_KEY` | Supabase service role key (not anon) |
| `OPENAI_API_KEY` | Your OpenAI key |
| `ANTHROPIC_API_KEY` | Your Anthropic key |
| `AGENT_API_KEY` | Generate: `openssl rand -hex 32` |
| `CORS_ORIGINS` | `https://your-frontend.vercel.app` |

### 1.4 Verify Deployment

```bash
# Check frontend
curl https://your-frontend.vercel.app

# Check API health
curl https://your-api.vercel.app/health

# Check docs
open https://your-api.vercel.app/docs
```

## Part 2: Set Up Supabase

### 2.1 Create Project

1. Go to [supabase.com](https://supabase.com) → New Project
2. Choose a region close to your VPS
3. Save the project URL and keys

### 2.2 Run Migrations

Apply all 21 migrations in order:

```bash
# Install Supabase CLI
npm install -g supabase

# Link to your project
supabase link --project-ref YOUR_PROJECT_REF

# Run migrations
for f in infra/supabase/migrations/*.sql; do
  echo "Running: $f"
  supabase db push --file "$f"
done
```

Or manually run each migration file in the Supabase SQL editor (`infra/supabase/migrations/001_*.sql` through `021_*.sql`).

### 2.3 Enable pgvector

In the Supabase SQL editor:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

This is already in migration 001 but verify it exists.

### 2.4 Verify RLS

All tables have Row Level Security enabled. Check in Supabase Dashboard → Authentication → Policies.

## Part 3: Create Telegram Bot

### 3.1 Create the Bot

1. Open Telegram, search for **@BotFather**
2. Send `/newbot`
3. Choose a name: `PositionedUp Jumbo` (or anything you want)
4. Choose a username: `positionedup_jumbo_bot` (must end in `_bot`)
5. Save the **bot token** (looks like `123456789:ABCdef...`)

### 3.2 Get Your Chat ID

1. Open Telegram, search for **@userinfobot**
2. Send `/start`
3. It replies with your numeric user ID (e.g., `123456789`)
4. Save this as your `TELEGRAM_OWNER_CHAT_ID`

### 3.3 Test the Bot

After deployment, message your bot on Telegram. Jumbo will respond.

## Part 4: Deploy Agent Squad to VPS

### 4.1 Provision the VPS

SSH into your VPS as root:

```bash
ssh root@YOUR_VPS_IP
```

Run the setup script:

```bash
# Option A: Run directly from repo
curl -fsSL https://raw.githubusercontent.com/YOUR_REPO/deploy/setup-vps.sh | bash

# Option B: Copy and run manually
scp deploy/setup-vps.sh root@YOUR_VPS_IP:~/
ssh root@YOUR_VPS_IP 'bash ~/setup-vps.sh'
```

This installs Docker, configures UFW firewall (SSH only), enables fail2ban, and creates directories.

### 4.2 Clone the Repository

```bash
cd /opt/openclaw
git clone YOUR_REPO_URL app
cd app
```

### 4.3 Configure Environment

```bash
cp deploy/env.example deploy/.env
nano deploy/.env
```

Fill in all values:

```env
# Gateway token (generated by setup script, or generate your own)
OPENCLAW_GATEWAY_TOKEN=your_64_char_hex_token

# LLM keys
OPENAI_API_KEY=sk-your-openai-key
ANTHROPIC_API_KEY=sk-ant-your-anthropic-key

# Telegram
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIjKlMnOpQrStUvWxYz
TELEGRAM_OWNER_CHAT_ID=123456789

# Brain connection (your deployed Vercel API)
AGENT_API_KEY=same_key_as_vercel_backend
POSITIONEDUP_API_URL=https://your-api.vercel.app
POSITIONEDUP_USER_ID=your_supabase_user_id

# Optional: PostHog analytics
POSTHOG_API_KEY=phc_your_key
POSTHOG_HOST=https://us.i.posthog.com
ANALYTICS_SYSTEM_ID=positionedup-squad
```

**Important:** The `AGENT_API_KEY` must match the one set in your Vercel backend. The `POSITIONEDUP_USER_ID` is your Supabase auth user ID (find it in Supabase Dashboard → Authentication → Users).

### 4.4 Build and Start

```bash
cd /opt/openclaw/app
docker compose -f deploy/docker-compose.yml up -d --build
```

This builds the Docker image and starts the OpenClaw gateway.

### 4.5 Verify It's Running

```bash
# Check container status
docker compose -f deploy/docker-compose.yml ps

# Check logs
docker compose -f deploy/docker-compose.yml logs -f

# Check health
curl http://127.0.0.1:18789/health
```

### 4.6 Access the OpenClaw Dashboard (SSH Tunnel)

The gateway is bound to loopback only (not exposed to the internet). Access it via SSH tunnel:

```bash
# From your laptop
ssh -N -L 18789:127.0.0.1:18789 root@YOUR_VPS_IP

# Then open in browser
open http://127.0.0.1:18789
```

Paste your `OPENCLAW_GATEWAY_TOKEN` when prompted.

## Part 5: Verify End-to-End

### 5.1 Message Jumbo on Telegram

Send your bot a message:
> "Hello Jumbo, what's the status?"

Jumbo should respond and appear in Mission Control.

### 5.2 Check Mission Control

1. Open your web app: `https://your-frontend.vercel.app/mission-control`
2. You should see:
   - Agent sidebar with 6 agents
   - Stats bar showing active agents
   - Live Feed button (toggle real-time messages)
   - Kanban task board

### 5.3 Verify Heartbeats

Agents check in every 15 minutes during active hours (7 AM – 11 PM ET). After 15 minutes:

```bash
# Check heartbeat logs
docker compose -f deploy/docker-compose.yml logs --since=15m | grep heartbeat
```

### 5.4 Create a Test Task

In Mission Control, click **+ New Task**:
- Title: "Research trending SaaS topics this week"
- Priority: P1
- Assign to: Jumbo

Jumbo will pick it up on his next heartbeat and delegate to Trend Analyzer.

## Part 6: Ongoing Operations

### View Logs

```bash
# All logs
docker compose -f deploy/docker-compose.yml logs -f

# Specific agent
docker compose -f deploy/docker-compose.yml logs -f | grep "jumbo"
```

### Restart Agents

```bash
docker compose -f deploy/docker-compose.yml restart
```

### Update Code

```bash
cd /opt/openclaw/app
git pull origin main
docker compose -f deploy/docker-compose.yml up -d --build
```

### Monitor Costs

- Check `/usage` page in the web app for LLM token tracking
- PostHog dashboard for agent activity metrics (if configured)
- Set budget alerts in OpenAI/Anthropic dashboards

### Backup

The important data is in Supabase (auto-backed up). Agent workspace files are in Docker volumes:

```bash
# Backup workspace
docker compose -f deploy/docker-compose.yml exec openclaw-gateway tar czf /tmp/workspace-backup.tar.gz /home/openclaw/.openclaw/workspace
docker cp openclaw-gateway:/tmp/workspace-backup.tar.gz ./workspace-backup-$(date +%Y%m%d).tar.gz
```

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Bot not responding | Check `TELEGRAM_BOT_TOKEN` and `TELEGRAM_OWNER_CHAT_ID` in `.env` |
| "Connection Error" on Mission Control | Verify API URL and that backend is deployed |
| Agents not showing up | Register agents via Agent Bridge API or wait for first heartbeat |
| Docker build fails | Check `docker compose logs` for errors |
| Health check failing | Run `curl http://127.0.0.1:18789/health` from the VPS |
| Agents not claiming tasks | Check active hours (7 AM – 11 PM ET) and heartbeat interval |
| High LLM costs | Lower heartbeat frequency or use GPT-4o-mini for more agents |
| SSH tunnel drops | Use `autossh` for persistent tunnels |

## Security Checklist

- [ ] `OPENCLAW_GATEWAY_TOKEN` is a random 64-char hex string
- [ ] `.env` file is NOT committed to git
- [ ] VPS firewall only allows SSH (port 22)
- [ ] Gateway is bound to loopback (not 0.0.0.0)
- [ ] `AGENT_API_KEY` matches between Vercel backend and VPS
- [ ] Supabase RLS is enabled on all tables
- [ ] fail2ban is running for SSH protection
- [ ] No hardcoded secrets in code
